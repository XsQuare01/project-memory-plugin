# /project — 프로젝트 메모리

모든 명령은 같은 꼴이다. 세션 ID 는 이 세션의 것(`${CLAUDE_SESSION_ID}`)을 그대로 넘긴다.

```bash
node <플러그인 폴더>/bin/pm.mjs <명령> … --agent claude --session ${CLAUDE_SESSION_ID}
```

기록 규칙 전체는 `<플러그인 폴더>/policy.md` 를 읽고 따른다.

## 하위 명령

| 사용자 입력 | 할 일 |
|---|---|
| `/project use <이름>` | `pm use <이름>` — 이 세션에만 적용. 다음 메시지부터 문맥이 들어간다 |
| `/project use --clear` | `pm use --clear` |
| `/project link <이름>` | 지금 작업 폴더(git 저장소)에서 `pm link <이름>` — 이 브랜치를 프로젝트에 연결. 사용자 저장소의 로컬 `.git/config` 에 `branch.<브랜치>.pm-project` 를 쓴다고 알린다 |
| `/project unlink` | `pm unlink` |
| `/project new` | 아래 "새 프로젝트" |
| `/project status` | `pm status` — 판정과 주입될 글을 그대로 보여 준다 |
| `/project save` | 아래 "세션 마무리" |
| `/project view` | `pm view` — 브라우저로 뷰어를 연다 |
| `/project` (인자 없음) | `pm status` 를 보이고, 쓸 수 있는 하위 명령을 한 줄씩 안내한다 |

## 사용자 메모리

사용자에 대한 정보(배경·선호·동료 역할·환경)는 `pm me` 로 다룬다. 규칙은 policy.md 의 "사용자 메모리" 절.

| 사용자 입력 | 할 일 |
|---|---|
| "앞으로는 …", "나는 보통 …" | `pm me remember --id … --text … --kind … --scope … --source "<날짜> 대화 — \"<원문>\"" [--core]` |
| "그거 맞아/이렇게 고쳐" | `pm me list` 로 판번호 확인 → `pm me confirm <id> --base <판번호> [--text …]` |
| "그건 잊어" | `pm me forget <id>` |
| `/project me` | `pm me list` |

## 새 프로젝트

1. 사용자에게 과제가 무엇인지 한두 문장으로 묻는다(이미 대화에 있으면 생략).
2. 이름 후보를 2~3개 낸다. 규칙: 영문 소문자·숫자·하이픈, 40자 이내, **과제**를 가리킴(기능·브랜치 이름 금지). 회사 과제 코드가 있으면 앞에(예: `p1234-acme`). 한 번 정하면 바꾸지 않는다고 알린다.
3. 사용자가 고르면: `pm new <이름> --title "<한글 제목>" --summary "<한 줄>" [--repo <저장소 식별자>]`.
4. 이어서 연결할지(`link`) 이 세션만 쓸지(`use`) 묻는다.

## 세션 마무리 (`save`)

1. 이 세션에서 나온 것 중 policy.md 의 "언제 쓰나"에 해당하는데 아직 기록하지 않은 것을 훑는다: 사용자의 정정·확인, 고른 결정, 외부 확인이 필요한 질문, 근거 있는 새 해석.
2. 목록을 사용자에게 보여 준다(항목마다 어느 파일에 어떤 상태로 쓸지).
3. 사용자가 고른 것만 `checkout → 변경안 수정 → apply` 로 기록한다. 사용자의 확인이 있었던 것은 `--confirm`.
4. 작업 상태(미커밋, PR 대기 등)는 넣지 않는다.

## 쓸 때 주의

- 정본을 직접 고치거나 셸로 쓰지 않는다. 변경안만 고친다.
- `apply` 가 종료 코드 3(충돌)이면 `checkout --refresh <경로>` 뒤 상대 변경을 살려 다시.
- 커밋은 `pm` 이 한다(프로젝트 메모리 저장소의 의도한 예외). `git commit` 을 직접 치지 않는다.
- 서브에이전트에게 메모리 쓰기를 맡기지 않는다.

# 프로젝트 메모리 (Codex)

플러그인 폴더는 이 SKILL.md 에서 네 단계 위(`../../../..`)다. 모든 명령은 같은 꼴이다.

```
node "<플러그인 폴더>/bin/pm.mjs" <명령> … --agent codex
```

- 세션 ID 는 Codex 가 명령 환경에 넣는 `CODEX_THREAD_ID` 를 `pm` 이 알아서 쓴다. 대화 문맥의 `[프로젝트 메모리]` 줄에 세션 ID 가 있으면 `--session <ID>` 로 넘겨도 된다.
- 기록 규칙 전체는 `<플러그인 폴더>/policy.md` 를 읽고 따른다.
- 저장 위치: 환경 변수 `PM_ROOT`·`PM_ME_ROOT` → `~/.project-memory/config.json` 의 `projectRoot`·`personalRoot`(Claude 플러그인 옵션이 남긴 값을 같이 쓴다) → 기본 `~/project-memory`·`~/personal-memory`.

## 하위 명령

| 사용자 입력 | 할 일 |
|---|---|
| `use <이름>` | `pm use <이름>` — 이 세션에만. 다음 메시지부터 문맥이 들어간다 |
| `use --clear` | `pm use --clear` |
| `link <이름>` | 지금 작업 폴더(git 저장소)에서 `pm link <이름>`. 사용자 저장소의 로컬 `.git/config` 에 `branch.<브랜치>.pm-project` 를 쓴다고 알린다 |
| `unlink` | `pm unlink` |
| `new` | 아래 "새 과제" |
| `status` | `pm status` — 이번 세션에 실제 전달한 것과 지금 계산한 주입 글 |
| `save` | 아래 "세션 마무리" |
| `view` | `pm view` — 브라우저로 뷰어 |
| `me` | `pm me list` |
| (인자 없음) | `pm status` 를 보이고 하위 명령을 한 줄씩 안내 |

## 사용자 메모리

사용자에 대한 정보(배경·선호·동료 역할·환경)는 Codex memories 가 아니라 `pm me` 로. 규칙은 policy.md 의 "사용자 메모리" 절.

| 사용자 입력 | 할 일 |
|---|---|
| "앞으로는 …", "나는 보통 …" | `pm me remember --id … --text … --kind … --scope … --source "<날짜> 대화 — \"<원문>\"" [--core]` |
| "그거 맞아/이렇게 고쳐" | `pm me list` 로 판번호 확인 → `pm me confirm <id> --base <판번호> [--text …]` |
| "그건 잊어" | `pm me forget <id>` |

- "이번엔 …" 같은 한 번의 요청, 에이전트의 짐작은 기록하지 않는다.
- `text` 는 근거보다 강하게 쓰지 않는다.

## 새 과제

1. 과제가 무엇인지 한두 문장으로 묻는다(대화에 있으면 생략).
2. 이름 후보 2~3개: 영문 소문자·숫자·하이픈, 40자 이내, **과제**를 가리킴(기능·브랜치 이름 금지). 한 번 정하면 바꾸지 않는다고 알린다.
3. `pm new <이름> --title "<한글 제목>" --summary "<한 줄>" [--repo <저장소 식별자>]`
4. 연결(`link`)할지 이 세션만(`use`)인지 묻는다.

## 세션 마무리 (`save`)

1. 이 세션에서 policy.md 의 "언제 쓰나"에 해당하는데 아직 기록하지 않은 것을 훑는다. 압축으로 대화에서 사라진 부분은 세션 기록 파일(`~/.codex/sessions/…/rollout-*-<세션 ID>.jsonl`)에서 찾는다.
2. 목록을 보여 준다(항목마다 어느 파일에 어떤 상태로).
3. 고른 것만 `checkout → 변경안 수정 → apply`. 사용자 확인이 있었던 것은 `--confirm`.
4. 작업 상태(미커밋, PR 대기 등)는 넣지 않는다.

## 쓸 때 주의

- 정본을 직접 고치거나 셸로 쓰지 않는다. 변경안만 고친다.
- `apply` 가 종료 코드 3(충돌)이면 `checkout --refresh <경로>` 뒤 상대 변경을 살려 다시.
- 커밋은 `pm` 이 한다(과제 데이터 저장소의 의도한 예외). `git commit` 을 직접 치지 않는다.
- 메모리 쓰기는 메인 세션만. 서브에이전트에게는 읽을 파일 경로만 넘긴다.
- 사용자 메모리 내용은 사용자 요청 없이 PR·공유 문서에 넣지 않는다.
- 쓰기 명령(`checkout`·`apply` 등)은 과제 데이터 폴더에 쓴다. 샌드박스가 막으면 사용자에게 승인을 구한다.
